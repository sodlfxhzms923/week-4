# Code Review Guide

## 1. 리뷰 목적

코드 리뷰의 목적은 코드의 품질을 높이고, 오류를 사전에 발견하며, 개발 과정에서 개선 의견을 공유하는 것입니다.

모든 리뷰는 객관적이고 구체적인 근거를 바탕으로 작성합니다.

## 2. 리뷰 중요도 분류

### [MUST] 필수 수정

코드 병합 전에 반드시 해결해야 하는 문제에 사용합니다.

적용 기준:
- 실행 오류가 발생하는 코드
- 보안 또는 개인정보 보호 문제
- 필수 기능이 정상적으로 동작하지 않는 경우
- 프로젝트 요구사항을 충족하지 못하는 경우

예시:

`[MUST] 사용자 입력값이 GET 방식으로 전송되어 URL에 노출될 수 있습니다. 실제 정보 제출을 차단하거나 적절한 서버 처리 방식을 적용해 주세요.`

### [SHOULD] 개선 권장

정상 동작에 치명적인 문제는 아니지만 코드 품질이나 사용성을 높이기 위해 개선을 권장하는 경우에 사용합니다.

적용 기준:
- 중복된 코드
- 가독성이 떨어지는 코드
- 유지보수가 어려운 구조
- 모바일 대응 및 접근성 개선

예시:

`[SHOULD] 모바일 환경에서 고정된 여백으로 인해 화면이 좁아질 수 있습니다. 미디어 쿼리를 적용하는 것을 권장합니다.`

## 3. 리뷰 진행 절차

1. Pull Request의 변경 목적을 확인합니다.
2. Files changed에서 수정된 코드를 검토합니다.
3. 문제를 발견하면 해당 코드 줄에 댓글을 작성합니다.
4. 댓글 앞에 [MUST] 또는 [SHOULD] 태그를 표시합니다.
5. Finish your review에서 검토 결과를 요약합니다.
6. Submit review를 통해 리뷰를 제출합니다.

## 4. 리뷰 의견 작성 원칙

- 문제가 발생하는 코드 위치를 명확히 지정합니다.
- 문제의 원인을 설명합니다.
- 가능한 경우 개선 방법을 제시합니다.
- 개인적인 비난을 피하고 코드에 집중합니다.
- 실제 확인하지 않은 오류를 단정하지 않습니다.

## 5. 리뷰 반영 및 해결

코드 작성자는 리뷰 의견을 확인한 뒤 필요한 변경 사항을 반영합니다.

수정 후에는 Conventional Commits 형식의 커밋을 작성하고, 리뷰 댓글에 변경 내용을 답변합니다.

수정이 완료되고 검토가 끝난 대화는 Resolve conversation으로 처리합니다.

## 6. PR 병합 기준

- [ ] 필수 기능이 정상적으로 구현되어 있습니다.
- [ ] [MUST] 문제가 해결되었습니다.
- [ ] 개선 권장 사항을 검토하였습니다.
- [ ] 변경 사항이 커밋에 반영되어 있습니다.
- [ ] 리뷰와 테스트 결과를 확인하였습니다.

위 항목을 확인한 뒤 Pull Request를 병합합니다.
